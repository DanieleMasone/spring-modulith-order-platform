Spring Modulith Order Platform

A production-oriented modular monolith for order management, built with Java 21, Spring Boot 4, Spring Modulith, PostgreSQL, Flyway, OpenAPI-first contracts and Testcontainers.

Architecture

The service is intentionally a modular monolith: one deployment unit, strong transaction boundaries and explicit module contracts. Spring Modulith verifies that module dependencies remain acyclic and only target exposed API packages.

Generated OpenAPI types are outside the business modules and excluded from Modulith verification so generated code does not become an architectural module.

Modules

Customers

Owns customer identity and exposes a small lookup API for order validation.

Pricing

Owns catalog prices and creates deterministic quotes from product requests.

Orders

Coordinates customer validation, pricing, order persistence and order creation events.

Payments

Prepares payment records after orders are committed and authorizes matching amounts.

Notifications

Records notification intents created from order and payment events.

Generated API

OpenAPI interfaces and DTOs are generated during the Maven build.

Quality & Reliability

Architecture governance

ApplicationModules.verify() fails the build when module boundaries are violated.

Real persistence

Flyway owns schema changes and integration tests run against PostgreSQL with Testcontainers.

Problem details

REST errors use RFC7807 for validation failures, business rules and missing resources.

Generated Documentation

The Pages artifact is assembled from build outputs only. No generated report or generated OpenAPI page is committed to the repository.

Local Development

Start PostgreSQL with docker compose up -d, run verification with ./mvnw clean verify, then start the app with ./mvnw spring-boot:run.

CI/CD

The pipeline checks out the repository, sets up Java 21, runs one Maven verification, validates generated artifacts, validates Docker Compose, builds the Docker image and publishes target/pages.

Future Improvements

Possible next steps include richer order state transitions, shipment integration and production notification adapters. Distributed infrastructure remains deferred until concrete requirements justify it.
